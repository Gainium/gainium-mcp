# 002 — A deploy restarts every pm2 copy of this server, not only the ecosystem one

Bug spec (Definition / Evidence / Assumption).

## §1. Definition

`npm run pm:restart` is what the production deploy runs after `git pull` +
`npm run build`. It runs `pm2 restart ecosystem.config.cjs`, which restarts
only the processes *named* in `ecosystem.config.cjs`. A host can also run a
second copy of this checkout that was started by hand under another name with
its own environment (e.g. a read-only public endpoint). That copy keeps
serving the previous build after every deploy, so security and feature fixes
never reach it.

§1.1 Expected: after `pm:restart`, every pm2 process whose working directory
is this checkout is running the new build.
§1.2 Each extra copy keeps the environment it was started with — it is
restarted by pm_id with no `--update-env`.
§1.3 No extra copies → nothing happens, exit 0.
§1.4 A failed restart of any extra copy → exit non-zero (the deploy must not
look clean).
§1.5 Processes in other directories are never touched. No process name is
hard-coded; the ecosystem names are read from `ecosystem.config.cjs`.

## §2. Evidence

The production deploy logs of the last two releases show
`pm2 restart ecosystem.config.cjs` → `restartProcessId … (ids: [ 8 ])` only,
while `pm2 jlist` lists a second process with the same `pm_cwd` whose
`pm_uptime` predates both deploys.

## §3. Assumption

`pm2_env.pm_cwd` identifies a copy of this checkout. A process started from
this directory under a different name is, by construction, running this
build's `dist/`.
